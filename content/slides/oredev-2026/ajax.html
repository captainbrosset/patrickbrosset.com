--- title: Ajax notes: | While on the topic of SPAs, I want to tell the story of Ajax, which I always find fascinating, because it also shows how experimentation and developer creativity can drive the evolution of the web platform. Late 90s, Microsoft was building a new version of Outlook and wanted to make Outlook in the browser behave like the desktop application. But the web at the time was fundamentally not ready. The team wanted JavaScript in the page to be able to make an HTTP request in the background to get some data. So they worked with the IE team to create XMLHTTP, a component that wasn't part of IE technically, but exposed to it via ActiveX, something that only worked in ID: new ActiveXObject("Microsoft.XMLHTTP"). Outlook Web Access used it extensively essentially creating one of the very first single-page app. And other devs took notice of how powerful this was. Later, Mozilla implemented a compatible web API, no need for ActiveX. Followed eventually by Safari, Opera, and others: new XMLHttpRequest(). IE itself eventually added support in IE7. By the mid-2000s, sites such as Google Maps and Gmail demonstrated just how transformative this approach could be. This was later coined as AJAX by Jesse James Garrett in 2005. Then the web standards process caught up with reality. W3C began specifying XMLHttpRequest in 2006, largely converging on what the implementations already did, by reverse engineering. Years later again, we got a cleaner, more modern networking API: Fetch. const response = await fetch("/messages"); Product team needs something the platform can't do → hack is born → expectation of what the web can do changes → broader use happens → more implementations across browsers → first standard → better standard. Showing how developers pull the web towards new areas all the time. ---
